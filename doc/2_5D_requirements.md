# 2.5D BookSim 仿真器需求说明

## 背景与现状
- 现有 BookSim 以 2D 网络为核心，2.5D 场景仅能依赖拓扑无关的全局路由算法，将网络拍扁为平面拓扑进行分析。
- 全局路由需要完整网络信息，违背 2.5D 模块化设计初衷；当使用最短路径等全局路由时，互为反向的节点对路径相互逆向，无法形成跨子网的通道环路，因而无法模拟因子网间通道循环依赖导致的死锁。
- 当前模拟器只支持同步网络，而 2.5D 场景中芯粒与中介层解耦，通常工作在不同频率并需要跨时钟域通信。
- 参考 PANE 等基于 BookSim + OMNeT++ 的方案虽能通过握手控制链路还原异步通信，但模拟速度显著下降，需在保持精度与可扩展性间平衡。

## 设计目标
1. **分层/解耦建模**：芯粒网络与中介层网络独立建模，允许为每个子网定义独立的拓扑、路由和流量控制；通过网络间链路组合成完整 2.5D NoC。
2. **组合式路由**：无需全局网络知识，芯粒内部通信与芯粒-外部通信分离；提供子网交互协议以完成跨子网路由决策。
3. **跨时钟域支持**：各子网允许不同工作频率，提供统一时钟抽取与分发机制，以及跨时钟域握手通信方案。
4. **可见的死锁与性能行为**：能够模拟因子网间通道循环依赖产生的死锁，支持死锁检测/统计与可视化接口。
5. **可扩展性与性能**：在保持模块化的同时避免过度仿真开销，优先复用 BookSim 核心事件/管线模型。

## 功能需求
### 1. 网络建模
- 支持为每个芯粒定义独立的内部网络实例（建议默认集中式网格拓扑），允许自定义尺寸、端口映射、缓冲深度等参数。
- 中介层网络为独立实例，路由器扩展 4 个与芯粒互联的 I/O 端口（形成 4:1 互连），端口参数与芯粒侧可独立配置。
- 支持通过配置文件描述芯粒数量、位置/连接关系、各子网拓扑和链路参数；支持默认模板快速生成常见 2.5D 架构。

### 2. 组合式路由与映射机制
- 提供分段路由模型：
  1. 源芯粒内部路径（源节点 → 出口路由器）。
  2. 中介层/跨芯粒通道路径（出口路由器 ↔ 目的芯粒入口路由器）。
  3. 目的芯粒内部路径（入口路由器 → 目的节点）。
- 设计地址/坐标映射机制，将全局地址映射为「芯粒 ID + 芯粒内坐标」，并为跨芯粒流量提供可配置的出口/入口映射表。
- 芯粒与中介层路由算法可独立选择（XY、最短路、最小转弯、虚拟通道分离等），仅依赖本子网局部信息。
- 支持出口选择与入口落点的策略插件（基于映射表、哈希或策略脚本），以探索负载均衡与延迟/带宽权衡。
- 支持子网间路由协商接口：在出口处附加下一段路由提示（如目标芯粒 ID、入口端口），避免全局路由表。

### 3. 流量控制与握手协议
- 芯粒内部与中介层内部维持 BookSim 风格的同步管线（路由计算/VC 分配/交换分配/传输），支持现有流控策略。
- 子网间链路使用握手式异步通信：
  - 采用基于就绪/有效或请求/应答的信号对，显式建模跨时钟域的传输延迟。
  - 支持可配置的打拍/同步器级数与链路延迟，以反映物理实现差异。
  - 发送端在未获确认时保持 flit/credit，不依赖全局时钟。
- 提供基于 FreeRTOS 风格的事件/队列抽象：跨域链路视为事件队列，允许非阻塞、阻塞等待和超时配置。

### 4. 时钟与时间管理
- 设计统一的最小时间粒度 tick，按各子网频率对齐：
  - 计算全局最小公共时间单位，将其作为事件调度粒度。
  - 每个子网按自身频率在 tick 上生成本地时钟事件驱动管线级推进。
- 支持时钟比变化（整数/有理数），保证不同频率子网在时间线上保持精确对齐。
- 提供 API 监控各子网时钟事件、跨域同步开销及时间偏移。

### 5. 死锁/活锁可视化与调试
- 支持在跨子网路径上记录 VC 分配/占用，检测通道循环依赖：
  - 基于等待图或资源图的周期检测，涵盖芯粒内与中介层路由器 VC。
  - 允许用户注入故障/阻塞场景，验证死锁恢复策略（如超时重路由、抛弃包、专用解锁 VC）。
- 提供统计/日志接口：跨芯粒包延迟、跨域握手次数、同步器插入延迟、死锁检测告警。

### 6. 配置与可扩展接口
- 配置文件新增 2.5D 段落，描述芯粒列表、映射、互连链路、子网频率、握手参数等；保持与现有 BookSim 配置兼容（默认退化为 2D）。
- 插件式接口：
  - 路由策略、出口/入口映射策略、死锁恢复策略、握手协议变体可插拔。
  - 支持自定义事件回调，便于与上层系统联动或可视化。

### 7. 验证与性能要求
- 提供基准用例：
  - 单芯粒退化为 2D 场景，验证与现有 BookSim 等价。
  - 多芯粒 + 中介层的跨域案例，验证映射、握手、死锁检测。
- 性能指标：在典型规模（如 4 芯粒，每网格 4×4，虚拟通道数与缓冲深度与现状一致）下，仿真速度与原 BookSim 同量级，不超过可接受开销范围（例如 ≤2× 纯 2D 基线）。

## 非功能需求
- 保持代码模块化，避免全局耦合；新增子网/时钟/握手层应与核心路由/分配管线解耦。
- 文档与示例齐全：提供架构图、时序示例、配置样例与接口说明。
- 单元与集成测试覆盖新路由映射、握手跨域传输与死锁检测逻辑。

## 迁移/开发建议
- 优先在不改动核心 BookSim 事件模型的前提下，为子网和握手链路添加抽象层；必要时为跨域链路定义轻量事件驱动模型。
- 在实现顺序上先完成：配置扩展 → 子网建模 → 映射/分段路由 → 握手链路与时钟分频 → 死锁检测与可视化 → 性能优化。
